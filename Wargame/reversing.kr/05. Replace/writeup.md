# Replace 문제 Write-up

## 문제 정보
1. 문제 실행 시 윈도우 입력 폼이 하나 출력되나, 아무런 입력을 할 수 없는 상태로 "Wrong!" 문자열만 표시됩니다.
2. 정상적으로 입력 가능하도록 프로그램 조작이 필요한 상태입니다.
3. 프로그램 패치에 중점을 두고 작업을 진행합니다.

## 풀이 절차

### 1. 초기 분석
PEiD를 이용하여 문제의 환경을 확인한 결과, Visual C++ 6.0 기반 소프트웨어임을 확인했습니다.

### 2. 코드 분석
```assembly
mov dword_4084D0, eax    ; eax = 0x4F9 / dword_4084D0 = 0x4F9
call sub_40466F         ; sub_40466F 함수 실행
```

### 3. sub_40466F 함수 분석
1. `call loc_40467A`
   - eip를 0040467A로 이동

2. `mov dword_406016, 619060EBh`
   - 00406016 위치에 0x619060EB 값 입력
   - 해당 위치 근처에 "Correct!" 메시지 호출 함수 존재

3. `call $+5`
   - 현재 위치(00404684)에서 +5한 값(00404689)으로 이동

4. `inc dword_4084D0`
   - dword_4084D0 = <입력값> + 1

5. `retn` 실행
   - 현재 eip 주소에서 4만큼 빠져나가며 한 번 더 실행
   - 결과: dword_4084D0 = <입력값> + 2

6. 00404674의 해석되지 않는 코드:
   ```assembly
   add dword ptr [004084D0], 601605CAh  ; 004084D0 위치에 601605C7 더하기
   ```

7. 연산 결과
   - 4~5 과정 다시 호출하여 값 추가
   - 최종 결과: 004084D0 = <입력값> + 2 + 0x601605C7 + 2 = 0x601605CA + <입력값>

8. 최종 단계
   ```assembly
   mov ptr [eax], 90h
   retn
   ```
   - eax에 있는 값의 위치가 참조 가능한 경우, NOP 코드로 덮어씌워짐
   - 이 과정이 2번 실행되면서 NOP 코드로 인해 분기가 변경되어 "Correct!" 메시지로 변경
   - 7단계까지의 결과로 EAX에 0x401071이 저장되면, 해당 위치의 JMP(EB 11) Instruction 코드를 1바이트씩 2번 NOP로 수정하여 분기 수정 가능

## ⚠️ 주의 사항
Windows 10에서는 NOP 코드 분기가 정확하게 동작하지 않는 현상이 발생합니다. 정확한 실습을 위해서는 하위 버전의 Windows에서 실습하는 것을 추천드립니다.
